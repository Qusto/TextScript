# Data Model: StyleGuard Eval Harness

**Feature**: 003-style-eval-harness
**Date**: 2025-11-03
**Phase**: 1 - Design & Contracts

## Overview

StyleGuard uses a file-based data model with structured directories and JSON/text files. This document defines all data structures, file formats, and directory layouts used by the system.

## File System Structure

### Input: Text Corpus

User-provided corpus of author texts for dataset generation.

```text
corpus/
├── [author_name_1]/           # One directory per author
│   ├── text_001.txt
│   ├── text_002.txt
│   └── ...                    # Multiple text files (10+ required)
├── [author_name_2]/
│   └── ...
└── ...
```

**Requirements**:
- Author directories must contain at least `min_texts_per_author` files (default: 10)
- Text files must be UTF-8 encoded plain text
- File names can be arbitrary but must have .txt extension
- Directory names become author identifiers in output

### Output: Evaluation Dataset

Generated by `prepare_dataset.py`, consumed by `run_eval.py`.

```text
eval_dataset/
├── [author_name_1]/
│   ├── case_001/
│   │   ├── source_texts.txt        # Combined style reference texts
│   │   ├── ground_truth_article.txt # Original article for comparison
│   │   └── topic.json              # Neutralized topic and theses
│   ├── case_002/
│   │   └── ...
│   └── case_NNN/
│       └── ...
└── [author_name_2]/
    └── ...
```

**File Descriptions**:

1. **source_texts.txt**: Concatenated text from M style reference documents
   - Format: Plain text, UTF-8
   - Purpose: Input to style analysis
   - Size: Typically 50-200KB depending on source text lengths

2. **ground_truth_article.txt**: Single original text preserved as ground truth
   - Format: Plain text, UTF-8
   - Purpose: Reference for comparing generated article quality
   - Size: Typically 10-50KB (one document)

3. **topic.json**: Neutralized topic and content theses
   - Format: JSON (see schema below)
   - Purpose: Content-focused input for article generation (style removed)
   - Size: <5KB

### Output: Evaluation Results

Generated by `run_eval.py` for each evaluation run.

```text
eval_results/
└── [timestamp_YYYYMMDD_HHMMSS]/   # One directory per evaluation run
    ├── [author_name_1]/
    │   ├── case_001/
    │   │   ├── generated_article.txt         # Generated article output
    │   │   ├── metrics_numeric.json          # Cosine similarity, BERTScore
    │   │   ├── metrics_judge_content.json    # Content accuracy score (1-5)
    │   │   └── metrics_judge_style.json      # Style fidelity score (1-5)
    │   ├── case_002/
    │   │   └── ...
    │   └── case_NNN/
    │       └── ...
    ├── [author_name_2]/
    │   └── ...
    ├── _SUMMARY.csv               # Aggregated metrics across all cases
    └── _SUMMARY.md                # Human-readable summary report
```

**File Descriptions**:

1. **generated_article.txt**: Article generated by Ugly Script
   - Format: Plain text, UTF-8
   - Purpose: Output to evaluate against ground truth
   - Size: Typically 10-50KB

2. **metrics_numeric.json**: Numeric similarity metrics (see schema below)
3. **metrics_judge_content.json**: LLM judge content evaluation (see schema below)
4. **metrics_judge_style.json**: LLM judge style evaluation (see schema below)
5. **_SUMMARY.csv**: Aggregated metrics (see schema below)
6. **_SUMMARY.md**: Markdown report with statistics and interpretation

## Data Schemas

### topic.json

Neutralized topic and theses extracted from ground truth article.

```json
{
  "topic": "string (1-50 words)",
  "theses": [
    "string (neutral thesis 1)",
    "string (neutral thesis 2)",
    "... (5-10 theses total)"
  ]
}
```

**Example**:
```json
{
  "topic": "Journey through Paris during adverse weather conditions",
  "theses": [
    "Narrator is located in Paris",
    "Weather conditions: strong wind and rain",
    "Narrator experiences negative emotions",
    "Movement occurs on foot through city streets",
    "Time period: evening or night",
    "Narrator is alone during the journey",
    "Physical discomfort from weather is significant"
  ]
}
```

**Validation Rules**:
- `topic`: Non-empty string, max 100 characters
- `theses`: Array of 5-10 strings, each max 500 characters
- All text must be stylistically neutral (no metaphors, emotional language)

### metrics_numeric.json

Numeric similarity metrics computed from generated vs. ground truth.

```json
{
  "cosine_similarity": {
    "score": 0.85,
    "model": "all-MiniLM-L6-v2",
    "computed_at": "2025-11-03T10:30:45Z"
  },
  "bert_score": {
    "precision": 0.88,
    "recall": 0.86,
    "f1": 0.87,
    "model": "bert-base-uncased",
    "computed_at": "2025-11-03T10:30:48Z"
  }
}
```

**Field Descriptions**:
- `cosine_similarity.score`: Float [0.0, 1.0], higher = more similar
- `bert_score.precision`: Float [0.0, 1.0], how much of generated matches ground truth
- `bert_score.recall`: Float [0.0, 1.0], how much of ground truth covered by generated
- `bert_score.f1`: Float [0.0, 1.0], harmonic mean of precision and recall
- `computed_at`: ISO 8601 timestamp

### metrics_judge_content.json

LLM-as-Judge evaluation of content accuracy (generated vs. ground truth).

```json
{
  "score": 4,
  "reasoning": "TEXT_A covers most key ideas from TEXT_B including the main narrative arc and character development. However, it omits the subplot about the secondary character and condenses the ending. Overall strong content coverage with minor gaps.",
  "model": "openai/gpt-4o",
  "prompt_version": "content_judge_v1",
  "computed_at": "2025-11-03T10:31:15Z"
}
```

**Field Descriptions**:
- `score`: Integer [1, 5] where 1=completely different, 5=perfect coverage
- `reasoning`: String explaining the score (50-500 characters)
- `model`: Model ID used for judging
- `prompt_version`: Version identifier for prompt used
- `computed_at`: ISO 8601 timestamp

**Score Interpretation**:
- 1: Generated article is about completely different topic
- 2: Mentions topic but misses >50% of key ideas
- 3: Covers topic with notable gaps (25-50% missing)
- 4: Good coverage, only minor details missing (<25%)
- 5: Perfect coverage of all key ideas

### metrics_judge_style.json

LLM-as-Judge evaluation of style fidelity (generated vs. source texts).

```json
{
  "score": 3,
  "reasoning": "TEXT_A attempts to mimic the author's formal tone and uses some similar vocabulary. However, sentence structure is more generic and lacks the distinctive rhythmic patterns present in TEXT_B. Moderate style similarity.",
  "model": "openai/gpt-4o",
  "prompt_version": "style_judge_v1",
  "computed_at": "2025-11-03T10:31:45Z"
}
```

**Field Descriptions**: Same as content judge

**Score Interpretation**:
- 1: Completely different style, unrecognizable
- 2: Weak similarity (1 of 3 aspects match: tone/lexicon/structure)
- 3: Moderate similarity (attempts imitation but often generic)
- 4: Good similarity (most aspects match, recognizable style)
- 5: Perfect similarity (indistinguishable from author's writing)

### _SUMMARY.csv

Aggregated metrics across all test cases in evaluation run.

```csv
author,case,cosine_sim,bert_f1,content_score,style_score
mark_twain,case_001,0.85,0.87,4,3
mark_twain,case_002,0.82,0.84,3,4
dickens,case_001,0.79,0.81,4,4
[...],
MEAN,,0.823,0.840,3.8,3.7
MEDIAN,,0.820,0.835,4.0,4.0
STD,,0.045,0.038,0.6,0.5
```

**Columns**:
- `author`: Author name (string)
- `case`: Case ID (string)
- `cosine_sim`: Cosine similarity score (float)
- `bert_f1`: BERTScore F1 (float)
- `content_score`: Content judge score (integer)
- `style_score`: Style judge score (integer)

**Aggregate Rows** (last 3 rows):
- `MEAN`: Mean values across all test cases
- `MEDIAN`: Median values
- `STD`: Standard deviation

## Configuration Schemas

### dataset_config.yml

Configuration for dataset builder (`prepare_dataset.py`).

```yaml
# Input corpus location
corpus_path: "./corpus/gutenberg/"

# Output dataset location
output_path: "./eval_dataset/"

# Minimum texts required per author
min_texts_per_author: 10

# Number of texts to use for style reference
m_style_texts: 5

# Number of test cases to generate per author
k_test_cases: 5

# Model for topic neutralization
neutralizer_model_id: "anthropic/claude-3-5-sonnet-20240620"

# Maximum tokens to send to neutralizer (for cost control)
max_tokens_for_neutralizer: 4000

# Random seed for reproducibility (optional)
random_seed: 42
```

**Validation Rules**:
- `corpus_path`: Must be valid directory path
- `output_path`: Must be writable directory path
- `min_texts_per_author`: Integer ≥ 5
- `m_style_texts`: Integer ≥ 1
- `k_test_cases`: Integer ≥ 1
- Constraint: `m_style_texts + k_test_cases ≤ min_texts_per_author`
- `neutralizer_model_id`: Valid model ID (OpenRouter format)
- `max_tokens_for_neutralizer`: Integer > 0

### eval_config.yml

Configuration for evaluator (`run_eval.py`).

```yaml
# Input dataset location (from prepare_dataset.py)
dataset_path: "./eval_dataset/"

# Output results location
output_path: "./eval_results/"

# Model for article generation (Ugly Script)
generation_model_id: "meta-llama/llama-3-8b-instruct"

# Model for LLM-as-Judge evaluation
judge_model_id: "openai/gpt-4o"

# Numeric metrics configuration
metrics_numeric:
  cosine_similarity: true
  bert_score: true

# LLM judge metrics configuration
metrics_judge:
  content_judge: true
  style_judge: true

# Embedding model for cosine similarity
embedding_model: "all-MiniLM-L6-v2"

# Timeout for LLM API calls (seconds)
llm_timeout: 120

# Max retries for failed API calls
max_retries: 3
```

**Validation Rules**:
- `dataset_path`: Must be valid directory with dataset structure
- `output_path`: Must be writable directory path
- `generation_model_id`, `judge_model_id`: Valid model IDs
- `metrics_numeric`, `metrics_judge`: Objects with boolean values
- At least one metric must be enabled
- `embedding_model`: Valid sentence-transformers model name
- `llm_timeout`: Integer > 0
- `max_retries`: Integer ≥ 0

## Pydantic Models

These Python classes represent the data schemas and provide validation.

```python
from pydantic import BaseModel, Field, field_validator
from typing import List, Optional
from datetime import datetime

class TopicData(BaseModel):
    """Neutralized topic and theses (topic.json)"""
    topic: str = Field(min_length=1, max_length=100)
    theses: List[str] = Field(min_length=5, max_length=10)

    @field_validator('theses')
    def validate_theses_length(cls, v):
        for thesis in v:
            if len(thesis) > 500:
                raise ValueError(f"Thesis too long: {len(thesis)} chars")
        return v

class CosineSimilarityResult(BaseModel):
    """Cosine similarity metric"""
    score: float = Field(ge=0.0, le=1.0)
    model: str
    computed_at: datetime

class BERTScoreResult(BaseModel):
    """BERTScore metric"""
    precision: float = Field(ge=0.0, le=1.0)
    recall: float = Field(ge=0.0, le=1.0)
    f1: float = Field(ge=0.0, le=1.0)
    model: str
    computed_at: datetime

class NumericMetrics(BaseModel):
    """All numeric metrics (metrics_numeric.json)"""
    cosine_similarity: Optional[CosineSimilarityResult] = None
    bert_score: Optional[BERTScoreResult] = None

class JudgeResult(BaseModel):
    """LLM judge evaluation result"""
    score: int = Field(ge=1, le=5)
    reasoning: str = Field(min_length=50, max_length=500)
    model: str
    prompt_version: str
    computed_at: datetime

class DatasetConfig(BaseModel):
    """Configuration for dataset builder"""
    corpus_path: str
    output_path: str
    min_texts_per_author: int = Field(ge=5)
    m_style_texts: int = Field(ge=1)
    k_test_cases: int = Field(ge=1)
    neutralizer_model_id: str
    max_tokens_for_neutralizer: int = Field(gt=0)
    random_seed: Optional[int] = None

    @field_validator('k_test_cases')
    def validate_case_count(cls, v, values):
        m = values.data.get('m_style_texts', 0)
        min_total = values.data.get('min_texts_per_author', 0)
        if m + v > min_total:
            raise ValueError(
                f"m_style_texts ({m}) + k_test_cases ({v}) "
                f"exceeds min_texts_per_author ({min_total})"
            )
        return v

class EvalConfig(BaseModel):
    """Configuration for evaluator"""
    dataset_path: str
    output_path: str
    generation_model_id: str
    judge_model_id: str
    metrics_numeric: dict[str, bool]
    metrics_judge: dict[str, bool]
    embedding_model: str = "all-MiniLM-L6-v2"
    llm_timeout: int = Field(gt=0, default=120)
    max_retries: int = Field(ge=0, default=3)
```

## State Transitions

### Dataset Generation Workflow

```text
[Corpus Directory]
    ↓
[Scan Authors] → Filter by min_texts_per_author
    ↓
[For Each Author]
    ↓
[Random Split] → style_set (M texts) + test_set (K texts)
    ↓
[For Each Test Case]
    ↓
[Combine Style Texts] → source_texts.txt
    ↓
[Preserve Ground Truth] → ground_truth_article.txt
    ↓
[Neutralize with LLM] → topic.json
    ↓
[Save to eval_dataset/author/case_NNN/]
```

### Evaluation Workflow

```text
[eval_dataset/ Directory]
    ↓
[Load Test Cases]
    ↓
[For Each Test Case]
    ↓
[Load Files] → source_texts.txt, topic.json, ground_truth_article.txt
    ↓
[Generate Article] → Ugly Script with source_texts + topic
    ↓
[Compute Numeric Metrics] → cosine_similarity, bert_score
    ↓
[Compute Judge Metrics] → content_judge, style_judge
    ↓
[Save Results] → eval_results/timestamp/author/case_NNN/
    ↓
[Aggregate Statistics] → _SUMMARY.csv, _SUMMARY.md
```

## Entity Relationships

```text
Corpus
  ├─ 1:N → Author
  │         ├─ name: string (directory name)
  │         └─ 1:N → Text (*.txt files)
  │
Dataset
  ├─ 1:N → Author
  │         └─ 1:N → TestCase
  │                   ├─ case_id: string (case_NNN)
  │                   ├─ source_texts: Text (concatenated)
  │                   ├─ ground_truth: Text (original)
  │                   └─ topic: TopicData (neutralized)
  │
EvaluationRun
  ├─ timestamp: datetime
  ├─ config: EvalConfig
  └─ 1:N → TestCaseResult
            ├─ test_case: TestCase (reference)
            ├─ generated_article: Text
            ├─ numeric_metrics: NumericMetrics
            └─ judge_metrics: {content: JudgeResult, style: JudgeResult}
```

## Validation & Constraints

### File System Constraints

1. **Case Numbering**: Sequential starting from 001, zero-padded to 3 digits
2. **Author Names**: Must be valid directory names (no special chars)
3. **Text Encoding**: All text files must be UTF-8
4. **File Sizes**: Ground truth articles should be 1KB-100KB for meaningful evaluation

### Data Quality Constraints

1. **Topic Neutralization**: Theses must be factual, avoid metaphors/emotional language
2. **Metric Bounds**: All scores/metrics within documented ranges [0.0-1.0] or [1-5]
3. **Timestamp Format**: ISO 8601 for all datetime fields
4. **JSON Validity**: All JSON files must parse correctly

### Operational Constraints

1. **Disk Space**: Minimum 10GB free for typical dataset (100 cases)
2. **Memory**: Minimum 4GB RAM for BERTScore computation
3. **API Rate Limits**: Respect provider limits (typically 60 req/min)
4. **Reproducibility**: Same config + same random_seed → same dataset splits

## Migration & Versioning

### Version 1.0 (Initial)

All schemas defined in this document represent version 1.0 of the data model.

### Future Considerations

Potential schema evolution (not implemented yet):
- Add `model_version` field to topic.json for tracking neutralizer updates
- Add `execution_time` metrics for performance tracking
- Add `error_log` field in results for failed test cases
- Support multiple prompt versions simultaneously for A/B testing

### Backward Compatibility

When adding new fields:
1. Make new fields optional with defaults
2. Old data without new fields remains valid
3. Document migration scripts if breaking changes required
