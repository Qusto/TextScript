Техническое Задание и Спецификация: "StyleGuard: Eval Harness" v2.0

1.0 Обзор и Цели

1.1. Проблема

Существующий проект "Ugly Script" (система генерации статей по стилю) не имеет механизма для объективной оценки качества. Невозможно численно измерить:

Качество Промтов: Насколько хорошо промт style_analysis.txt улавливает стиль?

Качество Генерации: Насколько точно промт article_generation.txt следует стилю и теме?

Стабильность и Регрессии: Ухудшает или улучшает обновление промта/модели финальный результат?

1.2. Решение

Создание автоматизированной системы тестирования («Eval Harness») под названием "StyleGuard". Система будет состоять из двух независимых компонентов:

DatasetBuilder (Component A): Скрипт, который автоматически создает «золотой» набор тестовых данных из большого текстового корпуса (например, Project Gutenberg).

StyleGuard (Component B): Скрипт, который запускает "Ugly Script" на этом датасете и вычисляет метрики качества, используя как численные методы (BERTScore), так и LLM-as-Judge.

1.3. Схема Работы (High-Level)

[Корпус Текстов (Gutenberg)]
    |
    v
[Component A: DatasetBuilder (prepare_dataset.py)]
    |
    v
[eval_dataset/ (Папки с тестовыми кейсами)]
    |
    v
[Component B: StyleGuard (run_eval.py)] <--- [Ваш "Ugly Script" (как библиотека)]
    |
    v
[eval_results/ (Отчеты, JSON, метрики)]


2.0 Компонент A: DatasetBuilder

Имя скрипта: prepare_dataset.py
Задача: Создать структурированный набор тестовых данных (eval_dataset) из необработанного корпуса текстов.

2.1. Зависимости

Python 3.11+

openai (или anthropic для NEUTRALIZER_MODEL_ID)

pyyaml (для конфигурации)

tqdm (для индикатора прогресса)

2.2. Конфигурация (dataset_config.yml)

# Путь к необработанному корпусу. Ожидаемая структура: ./corpus/[author_name]/[text_file.txt]
corpus_path: "./corpus/gutenberg/"

# Куда сохранять готовый датасет
output_path: "./eval_dataset/"

# Настройки для отбора авторов
min_texts_per_author: 10 # Мин. кол-во текстов для обработки автора

# Настройки для разделения текстов
m_style_texts: 5         # Кол-во текстов для создания `source_texts.txt`
k_test_cases: 5          # Кол-во тестовых кейсов на автора (должно быть <= min_texts_per_author - m_style_texts)

# Модель, используемая для "Нейтрализации" темы.
# Рекомендуется: claude-3-5-sonnet-20240620 или gpt-4o
neutralizer_model_id: "claude-3-5-sonnet-20240620"

# Макс. токенов для отправки "Нейтрализатору" (для экономии)

2.3. Интерфейс Командной Строки (CLI)

# Запуск с конфигурацией по умолчанию
python prepare_dataset.py

# Указание конкретного файла конфигурации
python prepare_dataset.py --config dataset_config.yml


2.4. Алгоритм Работы

Загрузить dataset_config.yml.

Рекурсивно просканировать corpus_path. Найти всех авторов, у которых >= min_texts_per_author текстов.

Для каждого такого автора:

Вывести в лог: Processing [author_name]...

Создать папку eval_dataset/[author_name]/.

Случайным образом разделить все тексты автора на 2 набора:

style_set (M текстов)

test_set (K текстов)

Подготовка Стиля: Прочитать и объединить все M текстов из style_set в один большой source_texts_content.

Подготовка Тестовых Кейсов (Цикл по test_set):

Для каждого из K текстов (напр., text_B1.txt):

Создать папку eval_dataset/[author_name]/case_001/.

Сохранить source_texts_content как case_001/source_texts.txt.

Сохранить text_B1.txt как case_001/ground_truth_article.txt.

Нейтрализация Темы (Ключевой Шаг):

Прочитать text_B1.txt, обрезать до max_tokens_for_neutralizer.

Вызвать LLM (NEUTRALIZER_MODEL_ID) с Промтом 1 (Нейтрализатор).

Полученный JSON ({"topic": "...", "theses": [...]}) сохранить как case_001/topic.json. Примечание: Мы сохраняем JSON, а не topic.txt, так как структурированные тезисы более полезны для Ugly Script.

Вывести в лог: Dataset generation complete. Created K test cases for N authors.

2.5. Промт 1: "Нейтрализатор" (Component A)

Это промт для NEUTRALIZER_MODEL_ID. Он извлекает суть текста, очищая ее от стиля.

<System>
Ты — AI-аналитик с продвинутыми навыками семантического анализа и суммаризации. Твоя задача — деконструировать предоставленный текст, отделив его стилистическую форму от фактического содержания. Ты должен извлечь "что сказано", полностью проигнорировав "как это сказано".

Твоя цель — создать стилистически НЕЙТРАЛЬНЫЙ набор тезисов.
</System>
<User>
<Role>
Твоя задача — проанализировать следующий текст и вернуть JSON-объект с двумя ключами:
1.  `"topic"`: Нейтральная, энциклопедическая тема текста в 1-5 словах.
2.  `"theses"`: Массив (array) строк, содержащий от 5 до 10 ключевых тезисов, фактов или сюжетных точек из текста.

**Критические Требования к Тезисам (Theses):**
* **НЕЙТРАЛЬНОСТЬ:** Тезисы должны быть написаны сухим, безличным, "канцелярским" языком.
* **БЕЗ СТИЛЯ:** Избегай любых метафор, эмоционально окрашенной лексики, авторских оборотов или ритмической структуры оригинала.
* **ТОЛЬКО ФАКТЫ:** Извлекай только ключевые факты, события или аргументы.

**ПРИМЕР:**
* **Оригинал (Стиль):** "О, этот проклятый, промозглый ветер! Он выл, как голодный волк, терзая мою и без того измученную душу, пока я брел по бесконечным, грязным улицам Парижа, не видя ни зги..."
* **Плохой (Стиль сохранен):** ["Ветер выл, как волк", "Душа была измучена", "Улицы Парижа были грязными"]
* **Хороший (Нейтрализовано):** ["Повествователь находится в Париже.", "Погодные условия: сильный ветер.", "Повествователь испытывает негативные эмоции.", "Передвижение происходит пешком по улицам."]

**Формат ответа:** Только JSON.

<OriginalText>
{{ОРИГИНАЛЬНЫЙ ТЕКСТ (text_B1.txt) ВСТАВЛЯЕТСЯ ЗДЕСЬ}}
</OriginalText>

Проанализируй текст и верни JSON.
</User>
<Assistant>
```json

Загрузить eval_config.yml.

Вывести в консоль и сохранить в _SUMMARY.md агрегированные (средние) результаты.

4.0 Система Оценки (Метрики и Промты)

4.1. Числовые Метрики (Numeric Metrics)

Мы используем их для быстрого, дешевого и объективного измерения семантического сходства между сгенерированной статьей и эталоном.

M1: Cosine Similarity (Косинусное Сходство)

Что это: Математическая метрика, измеряющая угол между двумя векторами (эмбеддингами) в многомерном пространстве.

Как работает:

Мы берем generated_article и ground_truth_article.

Мы пропускаем оба текста через embedding_model (all-MiniLM-L6-v2), получая два вектора (например, размерностью 384).

Мы вычисляем косинус угла между ними.

Что измеряет: Только семантику. Насколько близки по смыслу два текста?

Интерпретация:

1.0: Идеальное совпадение по смыслу.

0.8 - 0.99: Отлично. Сгенерирован тот же смысл.

0.6 - 0.8: Хорошо. Основная идея та же, но есть расхождения.

< 0.6: Плохо. Тексты о разном.

M2: BERTScore

Что это: Более продвинутая метрика, которая использует эмбеддинги BERT и вычисляет оптимальное "спаривание" (matching) токенов между двумя текстами.

Как работает: Вместо одного вектора на весь текст, она сравнивает векторы каждого слова из generated_article с каждым словом из ground_truth_article.

Что измеряет: Семантику + Лексику. Насколько сгенерированный текст использует те же или синонимичные слова для выражения того же смысла?

Интерпретация: Возвращает 3 числа (Precision, Recall, F1). Мы смотрим на F1:

~0.9+: Очень хорошо (близко к рерайтингу).

~0.85 - 0.9: Хороший результат для генеративной задачи.

< 0.85: Средне или плохо.

4.2. Промты LLM-as-Judge (Точные Метрики)

Здесь мы измеряем то, что числа измерить не могут: стиль и качество.

4.2.1. Промт 2: "Оценщик Контента" (Content Judge - J1)

Задача: Насколько хорошо generated_article раскрыл тему из topic.json, сравнивая его с ground_truth_article (который является "идеальным" раскрытием темы).

Сравнение: generated_article ◄► ground_truth_article

<System>
Ты — AI-ассистент, выполняющий роль строгого редактора. Твоя задача — оценить, насколько полно и точно сгенерированная статья (TEXT_A) раскрывает ту же тему и идеи, что и эталонная статья (TEXT_B).

Ты должен вернуть JSON-объект с двумя ключами: "score" (число от 1 до 5) и "reasoning" (краткое объяснение).
</System>
<User>
<Role>
Оцени **полноту и точность содержания** TEXT_A по отношению к TEXT_B.
Игнорируй стиль, грамматику или форматирование. Сосредоточься только на том, **все ли ключевые идеи, факты и тезисы** из TEXT_B присутствуют и корректно изложены в TEXT_A.

**Шкала Оценки (Score):**
* **1:** TEXT_A полностью о другом. Идеи из TEXT_B отсутствуют.
* **2:** TEXT_A упоминает тему, но упускает >50% ключевых идей из TEXT_B.
* **3:** TEXT_A раскрывает тему, но с заметными пропусками (25-50% идей) или неточностями.
* **4:** TEXT_A хорошо раскрывает тему, упуская лишь мелкие детали (<25% идей).
* **5:** TEXT_A идеально раскрывает тему, покрывая все ключевые идеи из TEXT_B.

**Формат ответа:** Только JSON.

<TEXT_A>
{{СГЕНЕРИРОВАННАЯ СТАТЬЯ (generated_article.txt) ВСТАВЛЯЕТСЯ ЗДЕСЬ}}
</TEXT_A>

<TEXT_B>
{{ЭТАЛОННАЯ СТАТЬЯ (ground_truth_article.txt) ВСТАВЛЯЕТСЯ ЗДЕСЬ}}
</TEXT_B>

Оцени TEXT_A по 5-балльной шкале.
</User>
<Assistant>
```json


4.2.2. Промт 3: "Оценщик Стиля" (Style Judge - J2)

Задача: Насколько хорошо generated_article имитирует стиль source_texts?

Сравнение: generated_article ◄► source_texts

<System>
Ты — AI-ассистент, выполняющий роль опытного литературного критика. Твоя задача — оценить стилистическое сходство двух текстов. Ты должен вернуть JSON-объект с двумя ключами: "score" (число от 1 до 5) и "reasoning" (краткое объяснение).
</System>
<User>
<Role>
Тебе даны два текста:
* **TEXT_A (Сгенерированная Статья):** Статья, которая *должна* имитировать авторский стиль.
* **TEXT_B (Эталон Стиля):** Большой корпус текстов того же автора, определяющий эталонный стиль.

Твоя задача: Оцени, насколько хорошо TEXT_A **имитирует стиль** TEXT_B.
**Игнорируй тему и содержание.** Сосредоточься только на том, "КАК это написано":
* **Ритм и структура предложений** (короткие/длинные, простые/сложные).
* **Лексика** (выбор слов, терминология, метафоры).
* **Тон** (формальный, ироничный, мрачный, восторженный и т.д.).

**Шкала Оценки (Score):**
* **1:** Абсолютно непохоже. Стили диаметрально противоположны.
* **2:** Слабое сходство. Возможно, совпадает 1 из 3 аспектов (н-р, тон), но лексика и структура полностью отличаются.
* **3:** Среднее сходство. Текст "пытается" имитировать, но часто сбивается на генерический, безликий стиль.
* **4:** Хорошее сходство. Стиль узнаваем, большинство аспектов (тон, лексика, структура) скопированы верно.
* **5:** Идеальное сходство. Текст выглядит так, будто его действительно написал тот же автор, что и TEXT_B.

**Формат ответа:** Только JSON.

<TEXT_A>
{{СГЕНЕРИРОВАННАЯ СТАТЬЯ (generated_article.txt) ВСТАВЛЯЕТСЯ ЗДЕСЬ}}
</TEXT_A>

<TEXT_B>
{{ЭТАЛОН СТИЛЯ (source_texts.txt) ВСТАВЛЯЕТСЯ ЗДЕСЬ}}
</TEXT_B>

Оцени стилистическое сходство TEXT_A с TEXT_B по 5-балльной шкале.
</User>
<Assistant>
```json
